Универсальная обертка на Bash для безагентного сканера уязвимостей **[Vuls](https://github.com)**, работающая в изолированных контейнерах **Docker** или **Podman** без необходимости установки Go и зависимостей на хост-систему.

---

## О проекте

Для системного администратора ежедневный аудит безопасности и отслеживание новых уязвимостей вручную — трудоемкая задача. Официальный сканер **Vuls** решает эту проблему, автоматически сопоставляя установленные пакеты серверов с актуальными базами CVE, OVAL и эксплойтов.

**Vuls Container Runner** упрощает развертывание и эксплуатацию Vuls в любом Linux-окружении:
* **Гибкий выбор контейнерного движка:** по умолчанию скрипт автоматически определяет доступный рантайм (приоритет: `docker` -> `podman`), но также позволяет явно задать движок через флаг `--runtime`.
* **Zero-footprint на хосте:** весь цикл (загрузка баз, валидация конфига, сканирование по SSH и генерация отчетов) выполняется в эфемерных контейнерах (`--rm`).
* **Модульная конфигурация:** настройки баз данных (`db.toml`) и список целевых хостов (`servers.toml`) разделены на независимые файлы для удобного версионирования и генерации из внешних инвентарей.
* **Автоматизация SSH-доступа:** скрипт автоматически синхронизирует отпечатки хостов из `servers.toml` в `~/.ssh/known_hosts` и безопасно монтирует приватный ключ и `/etc/hosts` в контейнер без конфликта прав владельца.
* **Умное кэширование баз:** проверяет актуальность баз NVD, OVAL и ExploitDB, пропуская повторную загрузку, если базы уже обновлялись сегодня (с возможностью принудительного обновления через флаг `-f`).
* **Удобная текстовая отчетность:** в файл сохраняется полный детальный отчет по всем обнаруженным CVE, а в консоль выводится краткая однострочная сводка по каждому серверу.

## Основные возможности

* **Поддержка основных баз уязвимостей:**
  * **NVD** (`go-cve-dictionary`) — национальная база уязвимостей.
  * **OVAL** (`goval-dictionary`) — бюллетени безопасности конкретных дистрибутивов (Ubuntu, Debian, RHEL, Alpine и др.).
  * **ExploitDB** (`go-exploitdb`) — база публичных эксплойтов для приоритизации критичных CVE.
* **Безагентное SSH-сканирование:** проверка удаленных серверов по SSH-ключу без установки агентов на целевые узлы.
* **Совместимость с Rootless-режимом и SELinux:** корректная работа от имени непривилегированного пользователя и поддержка меток монтирования `:Z`.
* **Текстовые отчеты (`TXT`):**
  * **Консольный вывод (`-format-one-line-text`):** компактная сводка по количеству уязвимостей и обновляемых пакетов для каждого хоста без перегрузки терминала списком патчей.
  * **`results/full_report.txt` (`-format-full-text`):** полный детальный отчет со ссылками на бюллетени безопасности, описаниями CVE и затронутыми пакетами.

## Структура проекта

```text
.
├── vuls_runner.sh         # Основной исполняемый bash-скрипт
├── db.toml                # Конфигурация путей к базам данных SQLite3
├── servers.toml.example   # Шаблон списка сканируемых серверов и параметров SSH
├── .gitignore             # Исключения Git (базы данных, логи, отчеты, реальный servers.toml)
├── LICENSE                # Лицензия GPL-3.0
├── results/               # Директория с результатами сканирования и отчетами (создается автоматически)
└── logs/                  # Логи работы Vuls (создается автоматически)
```

## Требования

* Linux-хост с установленным **Docker** или **Podman** (если установлены оба инструмента, по умолчанию выбирается `docker`).
* Утилиты `ssh-keyscan` и `ssh-keygen` (из пакета `openssh-client`) для автоматического заполнения `known_hosts`.
* Доступ в интернет на хосте с запущенным скриптом для загрузки контейнерных образов (`docker.io/vuls/*`) и обновления баз уязвимостей.
* SSH-доступ от хоста со сканером до целевых серверов по ключу (`~/.ssh/id_ecdsa`). При использовании режима `fast-root` на целевых серверах Ubuntu/Debian требуется пакет `debian-goodies` (`checkrestart`).

## Быстрый старт

### 1. Клонирование и подготовка
Скопируйте файлы проекта в рабочую директорию, создайте рабочий конфиг серверов из шаблона и выдайте права на выполнение скрипту:

```bash
git clone <URL_вашего_репозитория> vuls-runner
cd vuls-runner
cp servers.toml.example servers.toml
chmod +x vuls_runner.sh
```

### 2. Настройка баз данных (`db.toml`)
Убедитесь, что в файле `db.toml` указаны пути внутри контейнера (`/vuls/...`):

```toml
[cveDict]
type = "sqlite3"
SQLite3Path = "/vuls/cve.sqlite3"

[ovalDict]
type = "sqlite3"
SQLite3Path = "/vuls/oval.sqlite3"

[exploit]
type = "sqlite3"
SQLite3Path = "/vuls/go-exploitdb.sqlite3"
```

### 3. Настройка целевых хостов (`servers.toml`)
Опишите ваши серверы в `servers.toml`. Общие параметры можно вынести в секцию `[default]`:

```toml
[default]
port        = "22"
user        = "kadm"
keyPath     = "/root/.ssh/id_ecdsa"
scanMode    = ["fast"] # Используйте "fast-root", если на узлах установлен debian-goodies и настроен sudo

[servers]

[servers.master]
host = "192.168.1.10"

[servers.worker1]
host = "192.168.1.11"
```

### 4. Настройка целевых ОС и SELinux в `vuls_runner.sh`
Откройте `vuls_runner.sh` и укажите дистрибутивы ваших серверов в массиве `OS_TARGETS`:

```bash
OS_TARGETS=(
    "ubuntu 24.04"
    # "debian 12"
)

# Если на хосте включен SELinux (RHEL, Fedora, Rocky, AlmaLinux), укажите:
VOL_OPTS=",Z"
```

## Использование

### Обычный запуск (автовыбор движка)
Определяет движок (`docker` или `podman`), синхронизирует `known_hosts`, проверяет актуальность баз, сканирует серверы, сохраняет полный отчет в `results/full_report.txt` и выводит в консоль краткую сводку:

```bash
./vuls_runner.sh
```

### Принудительный выбор контейнерного движка
Если на хосте установлены оба инструмента, можно явно указать нужный рантайм с помощью флага `-r` или `--runtime`:

```bash
./vuls_runner.sh --runtime podman
# или через короткий флаг
./vuls_runner.sh -r docker
```

### Принудительное обновление баз
Игнорирует дату локальных файлов `.sqlite3` и заново загружает данные из NVD, OVAL и ExploitDB перед сканированием:

```bash
./vuls_runner.sh --force-update
# комбинация флагов
./vuls_runner.sh -r podman -f
```

### Справка
```bash
./vuls_runner.sh --help
```

## Автоматизация (Cron)

Для ежедневного ночного аудита безопасности добавьте задачу в `crontab -e`:

```cron
0 3 * * * /opt/vuls-runner/vuls_runner.sh >> /opt/vuls-runner/logs/cron.log 2>&1
```

---

## Что Vuls НЕ делает

* Vuls **не устанавливает обновления** и не изменяет конфигурацию пакетов на целевых серверах — сканирование является полностью неразрушающим (read-only).
